# ProfileIT

*[English](README.en.md)*

섹션 기반 온라인 명함을 만드는 정적 사이트 생성기. 설정 파일 하나를 고치면
`dist/` 에 정적 파일 셋이 나오고, GitHub Pages 같은 곳에 그대로 올라갑니다.

학력·경력 타임라인, 버킷리스트, 관심사 태그, 링크 카드, 연락처를 섞어 쌓을 수
있고, 연락처는 방문자가 `.vcf` 로 받아 주소록에 바로 넣을 수 있습니다.
여러 언어로 만들 수 있고, 페이지에 언어 선택기가 붙습니다.

## 쓰기

데스크톱 앱으로 쓰는 쪽이 편합니다.

```bash
cargo run -p profileit-desktop
```

터미널이 편하면 CLI 도 그대로 있습니다.

```bash
cargo run -- edit           # 브라우저 편집 UI (로컬 전용)
cargo run -- build          # profile.toml → dist/
cargo run -- check          # 검증만
cargo run -- init           # 새 profile.toml 만들기
cargo run -- deploy         # 빌드 후 GitHub Pages 로 올리기
```

## GitHub Pages 에 올리기

편집기의 **GitHub 배포** 버튼(또는 `cargo run -- deploy`)이 `dist/` 를
`gh-pages` 브랜치로 올립니다. 올리기 전에 항상 다시 빌드하므로, 고친 내용이
빠진 채로 배포되는 일은 없습니다.

### GitHub 연결

상단 **GitHub 연결** 버튼이 순서를 안내합니다.

1. 토큰 발급 화면이 열립니다 (필요한 권한 `repo` 가 미리 선택됩니다)
2. 만든 토큰을 붙여넣으면 계정을 확인합니다
3. 저장소 목록에서 고르거나 새로 만듭니다 — 리모트가 자동으로 맞춰집니다
4. **GitHub 배포** 를 누르면 올리고 **Pages 도 자동으로 켭니다**

토큰은 **OS 자격증명 저장소**(Windows 자격 증명 관리자, macOS 키체인, Linux
Secret Service)에 보관됩니다. 설정 파일이나 앱 폴더에 평문으로 남지 않으므로,
프로젝트를 통째로 공유하거나 실수로 커밋해도 토큰은 따라가지 않습니다.

푸시할 때는 `GIT_ASKPASS` 로 넘깁니다. 명령줄에 붙이면(`https://토큰@...`)
프로세스 목록과 git 오류 메시지에 그대로 노출되기 때문입니다. 혹시 오류 메시지에
섞여 나오더라도 화면에 보이기 전에 지웁니다.

바깥 주소를 브라우저로 넘길 때 **셸을 거치지 않습니다.** 윈도에서
`cmd /C start` 를 쓰면 cmd 가 명령줄을 자기 규칙으로 다시 해석해서, 주소에 든
`&`·`|`·`%` 가 명령 구분자나 환경 변수 확장으로 동작합니다. 주소 하나로 다른
프로그램이 실행될 수 있습니다.

그 임시 스크립트는 공용 임시 폴더가 아니라 저장소의 `.git` 안에 만듭니다.
유닉스의 `/tmp` 는 누구나 쓸 수 있어서, 이름이 예측 가능하면 미리 심볼릭 링크를
걸어 엉뚱한 파일을 덮어쓰게 하거나 내용을 바꿔치기해 사용자 권한으로 코드를
돌릴 수 있습니다.

연결하지 않고 써도 됩니다. 그때는 이미 설정된 git 자격증명으로 푸시하고,
저장소 생성과 Pages 활성화는 GitHub 웹에서 직접 하시면 됩니다.

> **진짜 OAuth 로그인**(Authorize 버튼)은 OAuth App 등록이 필요합니다.
> `client_id` 를 발급받으면 기기 인증 흐름을 `src/github.rs` 에 더하면 되고,
> 나머지(저장소 목록·생성·Pages)는 그대로 씁니다.

작업 트리는 건드리지 않습니다. 브랜치를 체크아웃하지 않고 임시 인덱스로 커밋을
빚어 푸시하므로, 편집 중이던 파일이나 스테이징이 배포 때문에 흔들리지 않습니다.
`site.base_url` 이 실제 주소와 다르면 배포 후 경고로 알려줍니다 — 화면은
멀쩡한데 공유 카드만 엉뚱한 곳을 가리키는 고장을 미리 막기 위해서입니다.

출력은 `index.html`, `styles.css`, `card.js`, 그리고 설정이 참조하는 에셋뿐입니다.
서버가 필요 없습니다. 언어를 여러 개 쓰면 기본 언어가 `/`, 나머지가 `/en/` 처럼
하위 경로에 놓이고 에셋은 루트에 한 벌만 둡니다.

## 데스크톱 앱

[`src-tauri/`](src-tauri) 가 Tauri 껍데기입니다. 창과 메뉴만 담당하고, 편집·검증·
렌더링은 전부 `profileit` 라이브러리에서 옵니다. **편집 로직을 앱 쪽에 두지 않은
이유**는 그러면 검증 규칙이 두 곳에 생기고 둘이 어긋나기 시작하기 때문입니다.

앱과 라이브러리가 **같은 프로세스**라서 얻는 것이 둘 있습니다.

편집 서버를 스레드 하나로 띄웁니다. 자식 프로세스를 만들고 포트를 넘기고 뜰
때까지 기다리는 과정이 없고, 앱이 끝나면 서버도 같이 끝나므로 고아 프로세스가
남지 않습니다.

명함 폴더를 바꿀 때 서버를 다시 띄우지 않습니다. `Editor::open` 이 서버 상태만
바꾸고 창을 새로고침하면 끝입니다.

- **파일 → 명함 폴더 열기** (Ctrl+O) — 다른 폴더로 전환합니다. `profile.toml` 이
  없으면 만들지 물어보고 시작 파일을 씁니다. 있는 파일은 덮어쓰지 않습니다
- **파일 → 생성된 사이트 폴더 열기** — `dist/` 를 파일 탐색기로 엽니다
- 마지막으로 열었던 폴더를 기억했다가 다음 실행에 바로 엽니다

Windows 에서는 **WebView2 런타임**이 필요합니다. Windows 10/11 에는 대개 이미
들어 있습니다.

실행 파일로 포장하려면 `tauri.conf.json` 의 `bundle.active` 를 `true` 로 바꾸고
[Tauri CLI](https://v2.tauri.app/reference/cli/) 로 `tauri build` 를 돌리면 됩니다.

## 편집 UI

`cargo run -- edit` 이 `127.0.0.1` 에 작은 서버를 띄우고 브라우저를 엽니다.
왼쪽은 폼, 오른쪽은 **실제 렌더러 출력**을 담은 iframe 이라 미리보기가 결과물과
어긋날 수 없습니다. 상단 탭으로 편집할 언어를 고릅니다.

프로필 사진과 링크 썸네일은 파일을 골라 바로 올릴 수 있습니다. `assets/` 에
저장되고 설정에는 상대 경로가 들어갑니다. 확장자와 파일 내용을 함께 확인하므로
확장자만 바꾼 파일은 거부됩니다(8MB 이하, png·jpg·gif·webp·svg).

저장은 파일을 덮어쓰지 않고 **병합**합니다(`toml_edit`). 주석과 필드 순서,
여러 줄로 정렬해 둔 배열이 그대로 남습니다. 검증 오류가 있으면 저장하지 않고
화면 아래에 이유를 보여줍니다.

알아둘 점 두 가지입니다.

생략했던 기본값이 첫 저장에서 명시적으로 적힙니다(`enabled = true` 등). 편집기가
설정 전체를 보내기 때문인데, 기본값을 생략하면 일부러 적어둔 `done = false` 같은
값까지 지워질 수 있어 이쪽을 택했습니다. 두 번째 저장부터는 파일이 바뀌지 않습니다.

주석은 내용이 아니라 위치에 붙습니다. 편집기에서 섹션 순서를 바꾸면 주석은
제자리에 남아 엉뚱한 섹션을 설명하게 됩니다.

편집기가 필요 없으면 빼고 빌드할 수 있습니다.

```bash
cargo build --no-default-features
```

## 고치기

모든 내용과 모양은 [`profile.toml`](profile.toml) 한 파일에 있습니다. 필드
목록은 [`docs/schema.md`](docs/schema.md) 를 보세요.

```toml
[[sections]]
type = "timeline"
title = "학력"
icon = "🎓"

[[sections.items]]
period = "2014 – 2018"
title = "○○대학교 컴퓨터공학과"
subtitle = "학사"
```

섹션을 잠깐 숨기려면 지우지 말고 `enabled = false` 를 주세요. 대부분의 항목에도
같은 필드가 있습니다.

배경은 단색·그라디언트·무늬·이미지 중에서 고르고, 글씨는 한국어 웹폰트 프리셋을
이름으로 고릅니다 — CDN 주소를 찾아 넣을 필요가 없습니다.

```toml
[theme.background]
type = "pattern"
name = "dots"

[theme.font]
preset = "pretendard"
heading_preset = "jua"     # 제목만 다른 폰트로
```

## 여러 언어

번역이 필요한 값만 표로 바꾸면 됩니다. 나머지는 문자열 그대로 두고, 모든
언어가 같이 씁니다.

```toml
[site]
lang = "ko"                  # 기본 언어. 사이트 최상단(/)
languages = ["ko", "en"]     # 나머지는 /en/ 에 놓입니다

[[sections]]
type = "timeline"
title = { ko = "학력", en = "Education" }
```

번역을 별도 파일로 빼지 않고 설정 안에 두는 이유는, 번역이 원문 바로 옆에 있어야
빠뜨린 항목이 눈에 띄기 때문입니다. 경로로 연결하는 방식(`sections[1].title`)은
섹션 순서만 바꿔도 조용히 어긋납니다.

"연락처 저장" 같은 화면 문구는 `locales/<코드>.json` 에 있습니다. 한국어·영어·
일본어가 내장돼 있고, 같은 이름의 파일을 프로젝트에 두면 문구를 덮어쓸 수
있습니다 — 하나만 바꾸려고 파일 전체를 적을 필요는 없습니다.

**편집기 화면도 같은 세 언어로 바뀝니다.** 상단 오른쪽의 `KO EN JA` 로 고르고,
이 PC 가 기억합니다. 처음 열 때는 브라우저 언어를 따릅니다. 명함 내용의 언어와
**별개**입니다 — 한국어 화면으로 영어 명함을 쓰는 일이 흔하기 때문입니다.
편집기 문구는 같은 locale 파일에 `editor.` 로 시작하는 키로 들어 있습니다.

검증 오류·배포 오류처럼 **서버가 보내는 문구도 같이 바뀝니다.** 서버는 완성된
문장이 아니라 키와 인자(`msg.` 로 시작)를 보내고, 문장을 만드는 일은 화면이
자기 언어로 합니다. 터미널(`profileit build` 등)과 데스크톱 앱 메뉴는 화면과
따로 움직이는데, `PROFILEIT_LANG` 이 있으면 그것을, 없으면 명함의 기본 언어를
씁니다 — 메뉴는 창을 만들 때 한 번 그려져서 앱을 다시 열어야 바뀝니다.

빠진 번역은 기본 언어로 대체되고, 검증이 **언어당 한 줄**로 모아서 알려줍니다.

```
[경고] site.languages (en): 6개 항목에 en 번역이 없어 기본 언어(ko)로
       대체됩니다: site.title, site.description, profile.name, ... 외 2곳
```

## 검증

`build` 는 검증을 통과해야 실행됩니다. 깨진 결과물이 배포되는 것보다 빌드가
멈추는 편이 낫기 때문입니다.

**오류**는 빌드를 막습니다 — 없는 파일, `javascript:` 같은 위험한 URL, 잘못된
색상값, 형식에 맞지 않는 이메일·전화번호, 단위 없는 CSS 길이값.

**경고**는 빌드는 되지만 의도와 다를 가능성이 큰 경우입니다 — 섹션 키 오타,
폰트에 없는 굵기, 바탕색과 같은 무늬색, `done = false` 인데 달성 날짜가 있는 항목.

위치는 `sections[2].items[0].url` 처럼 TOML 경로로 표시됩니다.

## 구조

| 파일 | 역할 |
|---|---|
| `src/config.rs` | 스키마 정식 정의 |
| `src/validate.rs` | 검증 규칙 |
| `src/theme.rs` | `[theme]` → CSS 커스텀 프로퍼티 |
| `src/render.rs` | maud 템플릿 |
| `src/icons.rs` · `src/decor.rs` | 내장 SVG |
| `src/i18n.rs` | 번역 가능한 값(`Text`)과 UI 문구 |
| `src/message.rs` | 사용자에게 보일 문구의 키+인자 (`Message`) |
| `src/build.rs` | `dist/` 생성 |
| `src/save.rs` | 주석을 보존하는 저장 (편집기 전용) |
| `src/serve.rs` | 로컬 편집 서버 (편집기 전용) |
| `src/lib.rs` | 라이브러리 진입점 — CLI 와 앱이 함께 씁니다 |
| `src/init.rs` | 새 `profile.toml` 시작 파일 |
| `src/deploy.rs` | GitHub Pages 배포 |
| `src/github.rs` | GitHub 연동 (토큰 보관·저장소·Pages) |
| `static/` | 바이너리에 포함되는 스타일시트·스크립트·편집기 |
| `locales/` | UI 문구 |
| `src-tauri/` | 데스크톱 앱 (Tauri) |

스키마는 **편집 방식에 의존하지 않습니다.** 정적 렌더러와 로컬 편집 UI 가 같은
타입과 같은 검증 규칙을 씁니다. 나중에 브라우저 관리자 모드를 붙여도 마찬가지입니다.

`[theme]` 필드는 CSS 커스텀 프로퍼티와 1:1 로 대응합니다. `styles.css` 는
`--pf-*` 토큰을 소비만 하므로, 테마를 바꿔도 스타일시트는 캐시에 남고 편집 UI 는
변수만 갈아끼워 실시간 프리뷰를 만들 수 있습니다.

## 기여

아이콘과 폰트 프리셋을 늘리기 쉽게 열어뒀습니다.

- **플랫폼 아이콘** — `Platform` 에 변형을 넣고 `icons::platform` 에 한 갈래 추가
- **폰트 프리셋** — `FontPreset` 에 변형을 넣고 `family`·`stylesheet`·
  `available_weights` 채우기
- **장식 프리셋** — `DecorationPreset` 에 변형을 넣고 `decor::top`·`decor::bottom` 추가
- **언어** — `locales/<코드>.json` 을 만들고 `i18n::BUILTIN` 에 한 줄 추가.
  키가 빠지면 테스트가 잡아줍니다

```bash
cargo test
```
